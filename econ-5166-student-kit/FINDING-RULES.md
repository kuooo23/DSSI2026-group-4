# 學生資料到研究成果：共用規則

這份文件供課程 skills 共用，將教師規範轉成可執行的工作要求。先讀此文件，再依任務讀取 `templates/` 對應範本及 skill。

## 規範來源與適用範圍

- 本次新增交付要求僅依教師在對話貼出的「資訊搜集、統計分析（含圖表與迴歸）、Stata、預測模型」段落。原文來源：[finding 規範](https://docs.google.com/document/d/1sl6gEFMdmiGsiNjLe17UmZ30xKxq15U0Mb2B-Jvusxg/edit?tab=t.33iie8ybx7s4)，核對日期 2026-09-11。不要將其他章節或連結的內容擴張為本次要求。
- **一般統計與預測分析交付學生選定的 R Markdown (`.Rmd`) 或 Jupyter Notebook (`.ipynb`)，教師直接檢閱該檔案。** 教師最新指示已取代原文的同名 HTML 要求：不預設產生或要求繳交 HTML，只有使用者另外要求時才匯出。資訊搜集的純連結紀錄仍使用同名 Markdown。R 在此指 Rmd 分析文件，只有 `.R` 程式不能取代完整分析。Stata 按教師貼出的專用例外處理。
- 固定欄位以範本為底，教師貼出的內容補充摘要、圖表與模型呈現要求。預測範本補入舊範本缺少的敘述統計區塊。教師已取消會議日期命名與必交 HTML 要求；後續明確指示優先。
- 模擬維持既有 `.Rmd`／`.ipynb` 範本及學生選擇，不因本次規範新增必交 HTML、其他章節或額外績效指標。
- 偏好詢問、資料防洩漏、可重現性及未執行狀態等，是本工作包的操作補充，不冒稱為來源逐字規定。若來源將來更新，重新核對相關分頁後才修改本地規則，不猜測新要求。

## 命名、更新與交付

- 教師已取消來源文件中的「會議日期_內容描述」強制命名。本工作包沿用學生指定或既有檔名；新文件可取清楚描述內容的 basename，例如 `finding/rct_engagement.Rmd` 或 `finding/rct_engagement.ipynb`，依學生選定格式擇一交付。
- 不為命名要求學生提供會議日期，也不將會議日期列為產出前提。文件內原有 `Created At` 建立日期欄位保留。使用者另外要求 HTML 時，匯出檔才使用 Notebook／Rmd 的同一 basename。
- 資訊搜集／純外部索引的 `.md` 以外部檔案同一 basename 命名，例如 `survey-report.pdf` 對應 `survey-report.md`；Google Doc 用實際標題作為命名依據。檔名不明就詢問，不另套會議日期前綴。Stata 純索引沿用原紀錄及其 `.do`／文件的 basename。
- 統計／預測的 `.ipynb`／`.Rmd` 是正式可編輯分析文件，需有可重現程式、經實際輸出核對的發現與執行狀態。`.ipynb` 保留執行輸出；`.Rmd` 保留可執行程式與已確認的發現。`.md` 摘要、`.R` 程式或聊天回答不能替代這份分析文件。
- 統計／預測提交到 GitHub 的成果為選定的 `.ipynb` 或 `.Rmd`，不再要求搭配 HTML。學生先建立自己的 repo 並用 VS Code clone／開啟，再於每次產出後自行檢閱、stage、commit 與 push；AI 不代做 Git 寫入。未完成 repo 設定時先請學生完成，可繼續討論與唯讀檢查，但不先寫入正式學生產物；教師維護範本及明確指定的隔離 Demo 不受這項學生前置步驟限制。外部文件建立與分享仍依各自任務的授權處理。
- 不因省略 HTML 而省略實際執行與結果核對。使用者另外要求 HTML 時，再匯出並核對與原文件一致的結果；既有 HTML 不會因修改 Notebook／Rmd 自動重製，應說明未更新的匯出檔可能仍反映舊結果。

## 貢獻與 commit 紀錄

**上課原則：所有 contribution 都必須記錄成 commit。** 程式、資料處理、raw／processed 資料說明、分析、提案與 `PROJECT.md` 維護都適用。外部文件或其他非檔案成果，須以已 commit 的實質說明或連結紀錄留存證據；不能宣稱外部文件本身已進入 Git。

隨成果更新 `PROJECT.md` 的 `Key Contributions` 表，每列保留 `Name | Contribution | Commit reference`，記錄誰、做了什麼，以及實際包含該成果的 commit 連結或 SHA。應檢查相關 diff 是否支持貢獻描述；只有檔案路徑、口頭描述或任意舊 commit 不足以完成紀錄。未 commit 標示「待提交」，reference 未核對標示「待核對」，都不能視為已完成貢獻紀錄。commit 次數或程式行數不能替代成果評估。

依 [學生 Git 流程](AGENTS.md#course-repository-and-git-workflow)，AI 提供本次待檢閱檔案與建議 commit 訊息，學生在 VS Code 自行操作。學生提交後，AI 才唯讀核對實際 commit 與成果並回填 reference；貢獻表的更新由學生於後續 commit／push 留存，不追記該表自身未來的 hash 造成無限循環。

未 commit 記「待提交」；已有支持成果的本地 commit，但遠端狀態不明時記「已 commit；推送待核對」，確認尚未推送時記「已 commit；待 push」。只有核對遠端目標分支確實包含該 commit 後，才能記「已推送並核對」。SHA、本地乾淨狀態或快取的 origin 分支不能單獨證明已 push；學生口頭回報而未獨立核對時保留「學生回報」標記。AI 不以 fetch／pull／sync 代替唯讀核對。

## 語言預設與學生偏好

先讀學生本次要求及專案 `PROJECT.md` 的設定。**報告預設使用繁體中文（台灣用語，zh-TW）**；學生已明確指定其他語言時優先沿用。未指定報告語言就直接採用預設，不再詢問，也不等待語言答覆。開始新任務時，只詢問尚未提供且真正需要的工具格式或任務資訊：

- 統計、預測、模擬與資料整理：Python／Jupyter Notebook (`.ipynb`) 或 R／R Markdown (`.Rmd`)？不要因為環境已有 Python，或舊規則預設 R，就代學生選擇。
- Stata 任務：已明確選擇 Stata 就依其專用交付方式處理，不強迫改選 R／Python；只確認尚未提供的必要分析資訊。只有收到 `.dta` 不表示學生已選定 Stata。
- 報告內容、說明及圖表標籤使用台灣常見措辭與專業術語，例如「資料、變數、迴歸、程式、資訊」。不只轉換繁簡字形。固定範本欄位、程式識別名稱、檔案路徑、正式名稱及必要的原文引用保持原樣；學生指定其他語言時依其選擇。
- 學生另有指定工具、方法、圖表或說明深度時一併沿用；不要另開無關的偏好問卷。

範例問法：「你想用 Python／Jupyter Notebook 還是 R／R Markdown？」若研究目的、目標變數或作者也缺少，合併為一次簡短詢問。只問當前任務真正需要、尚未提供的資訊。

**學生尚未回覆必要的工具格式選擇時，可先讀檔、確認欄位和範本，但先不要建立正式產出、改動資料或執行分析。** 未指定報告語言不屬於等待條件。時間經過不等於已回答。學生明說「你幫我選」才可依既有程式與可用環境提出工具格式選擇，簡述理由後繼續。修改學生指定的既有 Notebook／Rmd 視為已指定格式，不必重新問。

偏好確認後，在本專案 `PROJECT.md` 的 `Student Preferences` 記錄學生明確選擇，以供後續任務沿用。採用預設語言時，保留「教師預設」註記，不冒稱學生已回答；不把教師在範本中的範例或另一份作業的作者當成學生。更新偏好不等於自動建立或定稿週報。若學生只要求閱讀，保持唯讀。

## 學生先提出初步想法

**學生必須先提出自己的初步想法，AI 才協助討論與發展研究方向。** 可以是自己注意到的現象、想理解的差異或初步疑問，並簡述為什麼想研究；不要求一開始就有成熟題目、模型或假說。沿用對話或 `PROJECT.md` 中已有的想法，不重複要求學生提供。

只有資料、只說一個大領域，或完全交由 AI「幫我想題目／全部決定」時，先請學生用自己的話說出觀察或疑問。可問：「你從資料或生活中注意到什麼現象？你想弄清楚什麼，為什麼？」也可提供留白句型「我注意到＿＿，想知道＿＿，因為＿＿」。此時不列候選題目、不替學生挑 outcome、不生成研究動機、假說或實質 proposal。

學生提供初步想法後，AI 可協助釐清問題、縮小範圍、檢查資料可行性、比較研究方法及改進題目表述；建議須連回學生的想法，研究決定仍依已確認內容處理。可以解釋作業格式或中立檢查資料的欄位與缺失，不藉此替學生選題。獨立的資料文件修正等工作，不因缺少新研究想法而額外設關卡。要求草稿也不等於已有想法；沒有想法時可提供空白架構，不能填入 AI 自創的實質研究內容。

## Proposal 採分階段討論

**撰寫 proposal 時，AI 預設擔任討論與寫作教練。** 學生先說明自己的想法與理由，AI 再協助釐清與組織文字；有題目並不代表可以代替學生決定所有指標、方法、假說與研究動機。

每輪聚焦目前最需要釐清的 1–2 個問題。先簡短回應學生剛才的想法，指出一個需要補充或檢驗之處，再邀請學生說明理由、取捨或用自己的話重述。不要一次丟出完整研究設計問卷，也不要自己回答剛提出的問題、連續推進尚未討論的章節。可提供簡短例子或少量有依據的方法選項，但要讓學生解釋選擇與其題目的關係，不以「AI 寫完、學生只回答好」取代討論。

依需要討論研究問題與動機、資料範圍與變數、方法與假說、限制及已確認分工。每一部分有足夠依據後，才整理相應段落；先保持未討論的設計為待確認，不用通用段落填滿。重要設計已有學生提供或確認的內容時，沿用並整合六章節，不為湊回合而重問，也不要求每次文字修正都重新批准。

研究決定或討論階段有變動時，在 `PROJECT.md` 的研究脈絡中簡記目前討論到哪裡、學生已確認的設計及下一個待討論問題，區分 AI 建議與已確認決定；純措辭修正不需新增討論紀錄。只要求某節或討論時，完成該範圍；「幫我寫 proposal」不等於授權 AI 自行補齊研究決策。

教師明確要求 Demo 或委託代作時，依本次明確範圍處理並標示示範設定；例如只委託示範分工，不自動擴張為代定整個研究設計或撰寫全篇。既有 Demo 文件不代表學生已討論、理解或認可其設計，也不作為往後學生流程的全面代作授權。

## 不確定的資訊先與學生討論

- 先查學生本次指令、已確認的 `PROJECT.md` 與來源文件。仍不確定的內容，不以常見做法或範本範例當成學生的答案。
- 研究問題、作者與來源、觀測單位、變數定義、樣本期間、刪除或補值規則、合併鍵、資料版本、訓練／測試切分、預測時點，以及會改變分析結果的模型設定若不明，先把當前任務需要釐清的事項合併詢問學生。可以提出選項與理由，但在學生確認或明確委託 AI 決定前，不把建議當成定案或先執行相依的處理／分析。
- **預設每組 3–4 位學生。** 這是課程預設，實際名單與人數以學生明確提供的資訊為準；不為湊足人數虛構成員，也不因預設人數自動分派 PM／DE／DA。尚未收到名單時，不把預設寫成已確認組員。
- **先問學生姓名與負責工作，分工由學生決定。** 開始小組專案時，先沿用對話、`PROJECT.md` 或 `TEAM.md` 已確認的資訊；缺少時主動問：「請提供你們這組各位成員的姓名與已確定負責的工作，並標明你是哪一位。」未分工者可先標待確認，不只留下「待填」卻不詢問。後續任務只補問相關的缺少資訊；已知姓名就只問缺少的工作，反之亦然，不重複要求全組名單。
- 不從 Git 作者、電腦帳號、檔名、教師範例或上傳者推測作者與職責，也不把目前對話的學生自動列為既有文件作者。AI 不自行指派 PM／DE／DA、不補造工作或承諾。確認後記入 `PROJECT.md` 的 `Team`：姓名填 `Name`，已確認角色與具體工作填 `Role`；新成果作者及貢獻歸屬依實際確認內容記錄，保留有依據的既有作者。不要為此額外索取當前任務不需要的個資。
- 姓名或工作尚未答覆、角色尚未分配時，先保持「待學生填寫／待確認」，可繼續不依賴歸屬的資料檢查或討論。草稿允許保留待補，但不能宣稱成員、作者或分工已確認；只知道 PM／DE／DA 等角色名稱時，仍須釐清當前任務需要的實際工作內容。
- 上述詢問用於學生專案流程；教師維護範本或只做格式驗收時保留占位欄位，不把教師當學生索取姓名與分工。
- 等待答覆時，可繼續唯讀檢查與不受該問題影響的工作。學生要求草稿或教師明確要求格式驗收時，未知處保留待補，列出需討論事項；不能因為留下「待補」就先執行依賴未知設定的工作。
- 已確認的資訊、既有授權及明確的委託沿用，不重複詢問。未指定報告語言時仍使用繁體中文與台灣用語；這項教師預設不需要另問。實際執行可計算的數字、雜湊值與有依據的檔案日期也不由學生手填。

## 確認資料與任務

1. 辨識學生交付的是原始資料、已整理資料、程式、現有結果，還是外部連結。學生只說「幫我分析」且沒有自身想法時，依「學生先提出初步想法」先問其觀察或疑問，不能任選一欄當應變數或提供題目清單讓學生代選。
2. 缺少關鍵變數定義、觀測單位、prediction target、模擬 DGP 等會改變結論的資訊時，問學生。作者、來源、時間區間與研究動機不得捏造。學生希望先做草稿時，未知處明確寫「待學生提供」。
3. 真實資料來源存於 `data/raw/`，保持原始內容；複製外部已整理資料到 `data/processed/` 前仍須檢查其結構與品質並記錄來源。檔名或所在資料夾不能證明資料已清理。
4. 跨階段資料準備由 `data-preparation` 串接：原始資料說明用 `raw-data-documentation`；合併、reshape、清理、去重、缺失處理與切分用 `data-processing`；整理後資料說明與驗證用 `processed-data-documentation`。處理程式放 `data/code/`，衍生資料放 `data/processed/`，處理紀錄可追溯到原始輸入。不可把原始檔重新命名就宣稱完成清理。
5. 維護既有 raw／processed 資料說明時用 [maintain-data-documentation](skills/maintain-data-documentation/SKILL.md)，沿用文件格式，依實際變動更新內容與驗證。只更新專案脈絡、資料索引或貢獻表時用 [maintain-project-context](skills/maintain-project-context/SKILL.md)；資料技能仍可直接回填自己核對的索引列。文件或索引更新不等於重做資料處理或重跑 finding。
6. 統計／預測成果只從本專案 `data/processed/` 讀取分析資料；finding 中只做範本容許的簡單篩選與少量變數產生。模擬依 DGP 生成人工資料，不必先有實證資料。外部檔案登記也不需建立假資料。

## 資料銜接與檔案驗證

本節是確保資料與後續分析正確銜接的操作方式，不新增教師未要求的評分欄位或 HTML 交付。

1. **記錄實際資料檔。** 在 `PROJECT.md` 的 `Data Artifacts` 表，一個實際資料檔一列，使用 `Dataset | Role | Data file | Documentation | Processing notebook | Verification | SHA-256`。路徑相對於專案根目錄；文件中的連結則相對於該文件所在位置，含空格的連結可用 `<...>` 包住。`Role` 表明 raw、analysis、train、test 或有依據的其他用途；train/test 分列，不能只看檔名猜角色。尚未產生的資料不能登記成已驗證。表格是目前資料索引，舊版處理與限制留在相關 Notebook 的說明中。
2. **核對身分與用途。** 依學生明確指定的資料或索引中與問題相符的角色、樣本及定義選檔，讀取實際檔案與說明，核對 schema、所需欄位、觀測單位、key 與適用檢查；SHA-256 由實際檔案 bytes 計算。hash 只證明檔案身分，不證明資料已清理或適合該研究。多份資料仍無法判斷用途時才詢問，不以第一個 CSV、模糊檔名或修改時間選檔。
3. **連結來源與產物。** 原始說明連到不變動的 raw 檔；處理 Notebook 列出每個具名輸入、輸出及其說明；processed 說明列出實際資料檔、來源、產生它的 Notebook、角色、檢查與 hash。外部已整理資料可註明產生程式 `not available` 並保留真實來源；缺索引或 hash 時先檢查後補登記，不必為填欄位重做不必要的清理。單純 raw 檔的程式欄可記 `not applicable (source)`。
4. **使用可攜的精確路徑。** 從目前目錄往上，取最近同時含 `AGENTS.md` 與 `templates/` 的專案根目錄。所有讀寫參數使用專案相對路徑，不含開發者絕對路徑。核對實際解析後路徑位於預期目錄，支援檔名空格；不存在或越界時明確停止，不能往其他專案找替代檔。處理輸出只能寫進本專案 `data/processed/`，避免輸出與輸入碰撞；更新既有輸出時依已授權的資料更新範圍進行，不因範本的防覆寫提示重複要求已給的授權。
5. **在生成程式中固定輸入版本。** raw／processed 文件、處理 Notebook 與後續 finding 都將每個輸入的精確路徑和已核對 SHA-256 寫入程式，讀檔前檢查存在及 hash，讀入後核對必要結構。找不到檔案、內容不同或結構不符就停止；不可用當下 hash 直接覆蓋 expected hash 讓檢查永遠通過。尚未執行的草稿可保留占位及停止訊息；缺少 hash 工具時標為 pending 並說明，不能跳過驗證卻宣稱成功。
6. **驗證磁碟上的輸出。** 執行處理後，重新讀取每個已序列化的檔案，核對筆數、schema、key 及相關轉換結果，再計算輸出 hash，回填文件與索引。不能僅驗證記憶體中的物件。`Verification` 記錄執行日期、通過的實際檢查與限制；部分執行／失敗記為 pending／failed。新處理失敗後留下的舊檔不可冒充新結果；已寫出但未通過檢查的檔案也不可交接為 ready。由 AI 在核對結果後更新索引，不另建自動解析與重寫整份 Markdown 的任務執行器。
7. **後續分析讀取同一份資料。** 統計／預測只讀已核對的 `data/processed/` 檔案；finding 內的資料連結、實際讀檔路徑、角色與 hash 一致。預測分別綁定 train/test，依已定義的切分單位檢查重疊，不將同一份檔案充當兩種角色，也不將測試資訊用於訓練選擇。
8. **處理版本變更。** 已登記 hash 不符時，先依現有授權及處理紀錄確認是否為預期新版本，再重新檢查、更新該資料紀錄與本次產出的讀檔綁定；版本意圖不明才詢問，不默默換檔或重設 hash。指出已知讀取舊路徑／hash 的既有 findings；只有任務包含重分析時才重跑並更新選定的 Notebook／Rmd，否則說明哪些成果仍基於舊資料。HTML 僅在另外要求時匯出。更新索引本身不代表既有分析已更新。

## 產出位置與格式

- 統計、預測、模擬選用 `templates/finding/` 的對應範本，保留 Background 欄位、巢狀欄位及程式區塊順序，以實際結果回填 Main Findings。實質分析不能從精簡外部索引模板代替建構。資料整理選 `templates/data/`；Stata 與外部純登記保留精簡欄位，外部報告可選 `templates/report/`。保留未適用的原欄位並簡述理由。
- 一般統計／預測：Python → `.ipynb`，R → `.Rmd`，依學生選定格式交付，不預設產生 HTML。模擬依原範本輸出 `.ipynb`／`.Rmd`。外部純索引 → `.md`，不製作空 Notebook；Stata 完整交付如下。
- Finding 成果依上節選用有意義的 basename。資料整理依 skill 存於 `data/` 對應目錄；外部報告索引存 `report/`。輔助圖表可放成果旁的 `assets/<stem>/`，以相對路徑連結。不要覆寫範本。
- 模板中的 `/data/processed` 表示**專案內** `data/processed/`，不是電腦的根目錄。從專案根目錄或 `finding/` 開啟都須能定位檔案；以根目錄 `AGENTS.md` 與 `templates/` 為定位依據，勿寫開發者電腦的絕對路徑。
- 既有作者與日期有依據則保留。新建統計、預測與模擬文件的 `Created At` 用建立當天的固定文字日期 `YYYY-MM-DD`，不使用每次執行會改變的動態日期。資料文件依其原欄位分清收到日期及建立日期；外部登記的 `Date created` 是外部原件的建立日期，格式 `YYYYMMDD`，未知時標為待提供，不能以建立索引的今天代填。
- 不複製範本的 iris 範例數值、輸出或占位作者。清除與當前資料無關的輸出。把結果限制與未執行狀態寫在文件內，不能只在聊天最後提醒。

## 摘要、圖表與迴歸規則

本節是教師貼出的統計／預測要求，亦適用於 Stata 分析的圖表；不以此替其他任務增加必填分析。

統計及預測均需在正式分析／建模前，對所有用到的變數製作摘要。數值欄位包括 mean、min、q25、q50、q75、max、sd、N；類別欄位包括前十類的次數與比例。列出缺失數並說明有效 N 和百分比分母。預測應分開呈現 train/test，無 test 標籤時明確註明 target 摘要不可得；不能用測試集摘要反過來選特徵或調模型。

| 呈現類型 | 交付要求 |
| --- | --- |
| 圖 | 有標題、可理解的變數標籤、x/y 軸與圖例；避免文字或大量散點重疊。呈現平均或係數等估計量時附 95% 信賴區間並說明方法，勿把標準差或預測區間當成信賴區間。文字交代內容、樣本、研究問題與發現。 |
| 表 | 有標題、樣本數與可理解的欄名；文字說明樣本、結論及複雜／主觀定義。兩組比較時呈現各組平均、標準差、平均差及 t 檢定 p 值，依設計選適當檢定並說明。 |
| 迴歸 | 附估計樣本的 outcome 平均及 N；預設異質變異穩健標準誤（例如 HC1），有群聚設計時用適當 cluster-robust 並說明。註明類別參考組與固定效果；不傾印所有固定效果係數。不強制製作 LaTeX 表。文字交代樣本、標準誤與變數定義。 |

文件的 `0.90* / 0.95** / 0.99***` 在本工作包解讀為常用的 `p < 0.10 / 0.05 / 0.01` 星號門檻；標明門檻及實際 p 值，避免把信心水準直接當 p 值。遇到無法定義或估計的統計量，清楚標示原因，不填零、虛構數值或假造區間。

## Stata 專用交付

- 完整 Stata 分析使用同 basename 的 `.md`、`.do` 及 Google Doc。`.md` 依原模板保留 `Background` 與真實 `Link to Google doc`。
- Google Doc 按 `.do` 程式段落排列，每段下方插入對應的實際分析結果；圖表遵守上節規則。這是教師貼出的 Stata 例外，不要求另轉 Rmd／ipynb。
- 教師要求學生在 VS Code 將 `.md` 與 `.do` 一起 commit 並 push 到 GitHub，AI 不代提交。建立 Google Doc 及分享仍按已有授權執行；缺存取方式或尚未建立時，可先備妥可檢閱的文件內容，將連結標為待提供並說明尚未完成交付。純連結登記不必重新執行或重建整份分析。

## 預測的必要成果

- 連續 target：訓練及測試分別報 MSE、MAE；提供預測值分布圖、預測值對真實值圖、預測值對預測誤差圖，說明誤差正負定義。RMSE 或 R² 可另加，但不取代 MSE／MAE。
- 二元 target：訓練及測試分別報 Recall、Accuracy、AUC、F1-Score，並提供混淆矩陣。定義正類與閾值；AUC 使用連續機率或分數，不使用已切成 0/1 的預測類別。
- Test 沒有真實標籤時，仍可提供預測及其分布；需要真實標籤的指標、散佈圖或混淆矩陣標為無法計算。單一真實類別、零分母等情形說明限制，不捏造 AUC 或其他結果。多類／其他任務需說明適用的擴充指標，不假稱來源已指定。

## 結果與驗證

- 學生要求完整分析，且 repo、偏好與研究問題已確認時，完成所需的本地程式與執行；學生若只要程式、格式整理或唯讀檢查，尊重該範圍。Git 寫入由學生操作；發布、寄送、建立外部文件或更改分享權限依各自任務授權處理。
- 統計／預測：Jupyter 應從乾淨 kernel 順序執行，將實際輸出保留在 `.ipynb`。Rmd 可在乾淨 R 程序使用 `knitr::knit()`，將驗證輸出寫到暫存位置，核對實際表格與圖形，再把已確認的發現寫回 `.Rmd`；暫存驗證產物不要求交付。兩種格式都須保留可重現程式，並核對 Main Findings、數字、圖表與解釋是否一致。
- 交付前檢閱選定文件及實際執行結果：章節與說明完整，圖中文字未重疊，表格可讀，圖片／相對資源可用。`.ipynb` 的儲存輸出須與本次執行一致；`.Rmd` 的發現須有本次執行結果支持。若文件引用支援檔，需一起交付並驗證連結。只有使用者另外要求 HTML 時，才匯出同名 HTML 並檢查其結果與文件一致。
- 用 `knitr::knit()` 驗證 Rmd 時，設定 `knitr::opts_chunk$set(error = FALSE)`，遇到讀檔或程式錯誤即停止；不可只憑已產生暫存文件就判定成功。
- 環境缺依賴或執行失敗時，不改用學生未選的語言。保留可重現程式、執行方法和具體阻礙，標示未執行或部分執行。不以沒有 HTML 判定交付未完成；只有使用者另外要求 HTML 而尚未完成時，才列為該次未完成項目。不要捏造績效、顯著性、圖表或驗證通過。學生提供的結果應標為「學生提供，未重新執行」，除非已實際重跑。
- 檢查輸入存在、用到的欄位存在、樣本篩選／缺失處理說明，以及模板完整度。對類別百分比說明分母，對數值 N 說明有效觀測定義；空樣本、全缺失、單一類別等情況明確報告。
- 統計關聯不能自動寫成因果；預測績效不能自動寫成政策效果；模擬不等於證明。新加的方法選擇與假設須對學生可見。
- 統計／預測交付列出選定的 `.ipynb` 或 `.Rmd`；Stata 列出其專用文件；其他任務依原模板。簡述實際執行與提交狀態、主要結果及待補資訊；僅在另有匯出要求時報告 HTML 狀態。本次依教師貼出的段落及後續修訂，不聲稱遵守未納入的其他章節。
